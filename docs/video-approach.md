# 動画対応の方針（顔固定・まばたき動画）

設計書 v2 §20–24 / §36 Phase 4–6 に対応する検討メモ。
対象は「顔をほぼ動かさず、まばたきのみする動画」という具体的なユースケース。
表情変化が大きい動画への目元マスク拡張は [video-expression-matting.md](video-expression-matting.md) を参照。

## 検討した案: 毎フレーム差分

> まばたき前の動画 + リファレンス静止画 → 毎フレーム差分を取って抽出

**推奨しない。** 理由:

1. **まばたき中は未装着リファレンスと目の開き具合が一致しない。**
   差分の大部分が「まぶたの動き」になり、まつ毛の証拠として使えない。
2. **フレーム独立処理はちらつく。** 同じ毛先の Alpha がフレーム間で 0.7 → 0.3 → 0.8 と揺れる
   （設計書 §24 の Temporal Consistency 問題）。
3. **コストが高い。** matting は 1 ROI あたり約 1 秒。全フレームに対して回すのは無駄が大きい。

## 検討した案: 「抽出は 1 回、追従はランドマーク warp」（不採用）

```text
動画
 ├→ ベストフレーム選択（目が最も開いている、ブレが少ない）
 │     └→ 既存パイプラインで 1 回だけ抽出 → product_rgba（基準まつ毛レイヤー）
 └→ 全フレーム
       ├→ MediaPipe でまぶたランドマーク追跡
       ├→ 開き具合に応じて基準レイヤーを warp（根元を軸に回転 + 縦圧縮）
       └→ Alpha 合成
```

**不採用。** 抽出は 1 回で済みちらつきも起きないが、まつ毛レイヤーそのものを
非相似変形（根元を軸にした回転＋縦圧縮）で**形状ごと変えてしまう**ため、
「商品領域には相似変換（移動・縦横比固定の拡縮・回転・反転）のみ」という原則に反する
（静止画モードの再合成も warp を使うが、こちらは相似変換なので毛束形状・縦横比が崩れない）。
また閉じかけフレームの形状変化を warp では正確に追従できない。

## 採用: 目元領域まるごと差し替え方式（実装済み）

まつ毛だけを細かく抜くのではなく、**元動画の目元領域（まつ毛＋まぶた＋まばたきの動きごと）を
AI 加工画像の上に貼り戻す**。商品ピクセルは幾何変換せず、元フレームのまま使う（変形するのは AI 加工画像側）。

```text
動画
 ├→ フレーム分解 + 全フレームのランドマーク検出
 ├→ ベストフレーム選択（目が開いていて鮮明なフレーム）→ best_frame.png を出力
 │     └→ 外部 AI でベストフレームを加工（目元は変えない指示 / 保護マスク）
 └→ 全フレーム
       ├→ AI 加工画像を顔ランドマーク affine で当該フレームへ位置合わせ
       ├→ 元フレームの目元領域（フェザー付きソフトマスク）を上に貼り戻す
       └→ 再エンコード → output.mp4
```

要点:

- **商品ピクセルは合成段階では無変形。** マスクが 1.0 のコア領域は元フレームのピクセルをそのまま使い、
  warp が掛かるのは AI 加工画像側だけ（`warp_edited_to_frame`）。まばたきの形状変化も元動画の
  ピクセルそのものなので追従問題が存在しない。毎フレームの matting も不要で軽量。
  ただし境界のフェザー帯（0 < mask < 1）は AI 加工画像と混色し、出力は libx264 / yuv420p で
  再エンコードするので、最終 MP4 にはコーデック分の劣化（クロマサブサンプリング・量子化）が残る。
- 実装: `backend/video.py`（ベストフレーム選択・目元マスク・位置合わせ・合成・エンコード）、
  API は `POST /api/video/session` / `POST /api/video/compose` / `GET /api/video/{id}/output`。
  UI は「動画モード」タブ。
- **弱点: 目元周辺の肌も元画像のまま残る。** AI 加工で目元付近の肌色を大きく変えると
  境界に違和感が出る。UI の「目元領域の広さ」スライダーで貼り戻し範囲を調整でき、
  運用上は AI 加工指示で目元周辺を大きく変えないことを推奨。
- 毎フレーム差分は将来、境界の破綻検出（オクルージョン等）の検証用途に使える。

### ベストフレーム選択の指標（設計書 §21）

`sharpness`（Laplacian 分散）、`eye_open`（まぶた間距離 / 目幅）、`face_angle`、`exposure`。
まつ毛抽出用途では **eye_open が最大** かつ **sharpness が上位** のフレームを選ぶ。

## 顔追従のスタビライズ

手ブレ低減は有効だが、**汎用の映像スタビライザーより顔ランドマーク基準の安定化が適している。**
第一段階では、画像を顔固定座標へ往復変換せず、現在の合成に使う相似変換の時系列だけを平滑化する。

| 方式 | 基準 | 評価 |
|---|---|---|
| 相似変換パラメータの時間平滑化（採用） | 顔 | 現在のフレームごとの変換推定を平滑化する。変換推定回数とフルフレーム warp 回数を増やさず、検出点由来のジッターを抑えられる |
| 顔固定座標で合成して逆変換（保留） | 顔 | 顔は固定できるが、フルフレームの補間が2回増え、商品画素にも変換が掛かる。第一段階で効果が不足した場合だけ検討する |
| 汎用スタビライザー（`ffmpeg vidstab` 等） | 背景 | 背景基準で揃えるため顔の動きは残る。補助的な事前処理としてなら有用 |

保留案は次の処理になる。既存の `pipeline.align_b_to_a` と同じ考え方なので実装は流用できるが、
第一段階には含めない。

```python
m, _ = cv2.estimateAffinePartial2D(lms_frame[ALIGN_POINTS], lms_best[ALIGN_POINTS], method=cv2.LMEDS)
stabilized = cv2.warpAffine(frame, m, (w, h))  # 顔を基準フレームへ固定
# ... 合成 ...
out = cv2.warpAffine(composited, invert_affine(m), (w, h))  # 元のカメラの動きへ戻す
```

### 現状の揺れと対策範囲

現状の `compose_frames()` は、フレームごとに検出したランドマークから
`estimateAffinePartial2D()` で相似変換を求め、その未平滑化の変換を AI 加工画像へ直接適用している。
目元マスクも同じフレームの未平滑化ランドマークから毎回生成する。このため、実際には顔が静止していても、
検出点の数ピクセルの誤差が次の2か所へ現れる。

- AI 加工画像全体の位置・角度・大きさが細かく揺れる
- 元フレームを残す目元マスクのフェザー境界が細かく揺れる

対策の対象は、動画全体の背景ではなく、**AI 加工画像と目元マスクに共通して使う顔追従軌跡**とする。
元フレームの目元画素自体は warp せず、Generative Product Preserve の原則を維持する。

### 採用する方式: 相似変換パラメータの時間平滑化

各フレームで現在も計算している相似変換を1回だけ求め、その行列を時系列で平滑化してから合成に使う。
顔を固定座標へ warp して合成後に逆 warp する方式は、全画素の補間が2回増えて商品画素にも変換が掛かるため、
最初の実装では採用しない。

処理手順:

1. `lms_edited[ALIGN_POINTS]` から `lms_frame[ALIGN_POINTS]` への相似変換を
   `cv2.estimateAffinePartial2D(..., method=cv2.LMEDS)` で各フレーム1回だけ推定する
2. 2x3 行列を、画像原点基準の `tx` / `ty` ではなく、加工画像の顔中心位置 / `angle` / `scale`
   に分解する。`tx` / `ty` は回転・拡縮と連動するため、別々に平滑化すると顔中心を余計に動かしてしまう。
   角度は時系列処理の前に unwrap する
3. 推定不能値と、前後から大きく外れた値を無効値として扱う
4. 内部の欠損は前後の有効値から線形補間し、先頭・末尾の欠損は最寄りの有効値で埋める
5. 短い中央値フィルターで単発外れ値を除き、FPSから決める時間窓の平滑化を適用する。
   ただし生の軌跡との差を顔中心2px、回転0.5度、拡縮0.5%以内に制限し、意図的な急移動へ遅れず追従する
6. 平滑化後の4パラメータから相似変換行列を再構成する
7. その行列を AI 加工画像の `warpAffine` に使用する
8. 目元マスクには生ランドマークを使わず、AI 加工画像側の目ランドマークを同じ行列で移した座標を使う

目元マスクは十分に膨張した領域なので、対象としている「顔をほぼ動かさず、まばたきのみ」の動画では、
開閉するまぶたを固定形状へ変形させる必要はない。マスク内から採用する画素は常に当該フレームの元画素であり、
まばたきと商品形状はそのまま残る。表情変化が大きく固定形状のマスクで覆えない動画は、
この方式の対象を越えるため `video-expression-matting.md` の段階的方式へ送る。

### 計算量

`ALIGN_POINTS` は両目32点と鼻周辺10点の合計42点である。
`estimateAffinePartial2D()` は画像全体ではなくこの42点だけを処理し、しかも現行実装ですでに
各フレーム1回実行している。したがって平滑化によって変換推定回数は増やさない。

動画処理時間を主に占めるのは、各フレームの MediaPipe 顔検出、フル解像度の `warpAffine`、
および動画エンコードである。平滑化は4本の長さNの数列に対する処理なので O(N) であり、
これらと比べて十分小さい。最初の実装ではフルフレームの warp 回数も現状の1回から増やさない。

### 失敗時の扱い

- 一部フレームで顔検出に失敗した場合は、現在の「直前ランドマークを保持」ではなく、前後の変換を補間する
- 先頭または末尾だけ欠ける場合は最寄りの有効な変換を使う
- 有効な変換が動画全体で得られない場合は、現行と同様に合成せず元フレームを返すのではなく、
  APIで処理不能を明示する方向で検討する（互換性を確認してテストで確定する）
- 急な顔移動をすべてノイズとして消さない。平滑化窓はFPS基準の短時間に限定し、実移動を含む合成動画で確認する

### TDDによる実装プラン

実装は次の順で Red → Green → Refactor を行う。

1. 変換行列の分解・再構成
   - 平行移動、回転、等方拡縮を往復して元の行列へ戻るテスト
   - 角度が `+180°/-180°` をまたぐ系列で不連続にならないテスト
2. 欠損補間と外れ値除去
   - 中間欠損、先頭・末尾欠損、単発の大外れを含む合成系列のテスト
   - 有効値が1件もない場合の契約を表すテスト
3. 時間平滑化
   - 静止顔へ交互の微小ジッターを加え、平滑化後の分散が小さくなるテスト
   - 一定速度の移動と緩やかな回転を過度に止めないテスト
   - 24/30/60fpsで、おおむね同じ時間幅の平滑化になるテスト
4. `compose_frames()` への統合
   - 1フレームにつき相似変換推定が1回を超えないテスト
   - AI加工画像と目元マスクが同じ平滑化変換を使うテスト
   - マスクのコア領域では、合成直後の商品画素が元フレームと一致する既存条件の回帰テスト
   - 元フレーム自体へ `warpAffine` を適用しないことを確認するテスト
5. 動画レベルの回帰確認
   - 合成ランドマーク列を使い、静止区間のフレーム間変位が減ることを数値化する
   - 意図的なパン・顔移動とまばたきを含む短い動画で追従遅れ、境界外れ、端の欠けを確認する
   - 平滑化前後の処理時間を計測し、変換推定回数とフルフレーム warp 回数が増えていないことを確認する

完了条件は「見た目が良くなった」だけにせず、静止区間の変換パラメータの分散低下、
意図的な移動に対する最大追従誤差、商品コア画素の保持、処理時間の回帰を記録する。
閾値は実写サンプルを確認してから決め、合成データの絶対値を実写精度として引用しない。

2026-08-22 の実写サンプル（471フレーム）では、画像原点基準の平滑化は目中心の生軌跡から
最大約9.4px離れた。顔中心基準かつ補正量制限後は最大約2.1px、95%点約1.94pxとなり、
5フレーム以上継続して移動量1px未満だった区間の平均フレーム間移動は0.487pxから0.308pxへ減った。
これは当該サンプルで方式を比較した値であり、一般的な実写精度を示すものではない。

## 不自然になる場合のフォールバック

目元領域の境界がどうしても馴染まない場合は、その区間のみ
video matting へ切り替える 2 段構えとする。

- Promptable Video Segmentation + Tracking（SAM2 系）
- Temporal Matting（MatAnyone 系）

最初からこちらを採用しないのは、計算コストが高く、かつフレームごとに Alpha を推定するため
形状の同一性保証が弱まるため。

## 開発順序

1. フレーム分解 + ベストフレーム選択 → **実装済み**
2. 目元領域差し替え合成 + 動画書き出し → **実装済み**
3. 境界の色馴染ませ（color transfer）・顔ランドマーク基準スタビライズ
4. 差分による破綻フレーム検出
5. （必要なら）破綻区間のみ video matting
