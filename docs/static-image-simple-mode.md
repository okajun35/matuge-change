# 静止画モード：簡易モード仕様

## 1. 目的

静止画モードを初めて使う人が、抽出・Matting・再合成という内部工程を理解しなくても、
装着画像からまつ毛を抽出して AI 加工済み画像へ貼り戻せるようにする。

現行画面の調整機能は削除しない。通常は簡易モードだけを見せ、結果に問題がある場合だけ
「詳細調整」から現行機能を開く段階的開示とする。

## 2. 用語

- **装着画像**: まつ毛を装着した抽出元画像
- **AI 加工済み画像**: まつ毛を貼り戻す先の画像
- **未装着画像**: 差分推定に任意で使用する画像。簡易モードの必須入力にはしない
- **簡易モード**: 2画像の入力から解析・Matting・再合成までを一括実行する既定UI
- **詳細調整**: ROI、3値ブラシ、閾値、位置合わせ、レイヤー、商品登録、セッション操作を行う既存UI

## 3. 現行仕様

現行の静止画モードは、利用者が次の工程を個別に実行する。

1. 装着画像と任意の未装着画像を選択する
2. 正面の自動顔検出、または横顔・目のアップ用の手動 ROI-A を選択する
3. 「解析開始」で Probability、Trimap などを生成する
4. 必要なら3値ブラシと閾値を調整する
5. 「Matting実行」で Alpha と Product RGBA を生成する
6. AI 加工済み画像を選択する
7. 自動顔検出、または手動 ROI-B と相似変換で位置を決める
8. 「再合成」で完成画像を生成する

この画面は問題の診断と細かな修正には必要だが、最初から全操作が並ぶため、通常ケースでも
工程と専門用語を理解しなければならないように見える。

## 4. 簡易モードの画面

静止画モードを開いた直後は、次の要素だけを主操作として表示する。

1. 「装着画像」ドロップ領域
2. 「AI加工済み画像」ドロップ領域
3. 「処理を実行」ボタン
4. 「詳細調整を開く」ボタン

各ドロップ領域はクリックによるファイル選択にも対応し、画像選択後はサムネイルと
ファイル名を表示する。画像以外のファイルは受け付けず、理由をその場に表示する。

「処理を実行」は2画像が揃うまで無効とする。未装着画像は詳細調整内の任意入力として扱う。

## 5. 一括処理

「処理を実行」は既存の処理を次の順番で呼び出す。

1. 画像を確認
2. 目元を検出して解析（セッション作成）
3. まつ毛を抽出（Matting ジョブ）
4. AI 加工済み画像へ合成
5. 完成画像を表示

簡易モード専用の画像処理アルゴリズムや保存形式は作らない。既存の `/api/session`、
`/api/matte/jobs`、`/api/recompose` と同じセッションを使用する。

一括実行時の既定は正面向けの自動顔検出とし、ブラシ制約なし、既存の既定閾値を使用する。
実行のたびに新しいセッションを作成し、前回の手動調整を意図せず混ぜない。

## 6. 処理中モーダル

処理開始から成功または失敗までモーダルを表示する。内部用語ではなく利用者の作業として
次の段階を示す。

- 画像を確認しています
- 目元を検出しています
- まつ毛を抽出しています
- 加工画像に合成しています
- 仕上がりを準備しています

完了済み・実行中・未実行を視覚的に区別し、Matting ジョブの進捗値も進捗バーへ反映する。
処理中は多重実行を禁止する。

## 7. 成功後

完成画像を既存キャンバスに表示し、次の操作を提供する。

完成時は貼り戻しによって実際に変化した商品領域を中心に、最低100%の倍率で表示する。
画像全体を収める自動フィット（スマートフォン写真では5%前後になる）には戻さない。

簡易モードの表示切替は、利用者が比較する順に次の5つだけを提示する。

1. 装着画像（元）
2. AI加工済み画像
3. 合成結果
4. まつ毛の切り抜き
5. 透過マスク（Alpha）

上位3つを主要表示とし、切り抜きとAlphaは折りたたみの「抽出結果を確認」に置く。
Probability、Trimap、Difference、ROIなどの診断レイヤーは詳細調整だけに表示する。

- 完成画像を保存
- オリジナル装着画像と合成結果を左右に並べる比較モード
- 詳細調整を開く
- 別の画像でやり直す

比較モードは左に「まつ毛装着後のAI画像」、右に「オリジナル装着画像」を置く。
初期表示は左右それぞれのまつ毛領域を中心にしたフォーカス表示とし、単純な同一座標ではなく
各画像固有のフォーカス矩形を使用する。ズーム段階だけを同期し、「−」で
まつ毛 → 目元 → 顔 → 全体へ引き、「＋」で逆方向へ戻す。スマートフォンでは上下に並べる。

「詳細調整を開く」を選んだ場合、作成済みセッション、入力画像、Alpha、Product RGBA、
再合成結果を引き継ぐ。画像の再選択や解析のやり直しを要求しない。

## 8. 失敗時と詳細調整への誘導

HTTP エラーだけを失敗とみなさない。処理が完了しても、利用者が仕上がりを確認して
問題があれば詳細調整へ進める。

自動処理が失敗した場合は、モーダル内に理由と次の操作を表示する。

- 顔を検出できない: 手動 ROI-A を指定する詳細調整を開く
- まつ毛抽出に失敗: ブラシ・閾値を調整する詳細調整を開く
- 加工画像で顔を検出できない: 手動 ROI-B と位置合わせを行う詳細調整を開く
- 通信またはサーバーエラー: 再実行と詳細調整の両方を提示する

エラー時も、すでに作られたセッションと中間成果物を破棄しない。

## 9. 詳細調整の不変条件

- 現行の ROI、ブラシ、Undo/Redo、閾値、位置合わせ、レイヤー表示、商品登録、
  セッション再開・退避を維持する
- 表示専用レイヤーで `paintCanvas` のサイズを変更しない
- ズームとブラシ座標の変換を維持する
- レイヤー一覧の再構築時に `roi_b` と `composite_on_edited` を落とさない
- 商品領域に許す変換は相似変換と反転だけとし、自由変形やパースペクティブを追加しない

## 10. 今回の実装範囲

- 2画像のドラッグ＆ドロップとクリック選択
- 選択画像のサムネイルとファイル名
- 一括処理ボタン
- 処理段階と進捗を示すモーダル
- 成功後の完成画像表示、比較、保存
- 失敗時および任意のタイミングでの詳細調整への展開
- 詳細調整へのセッション・成果物の引き継ぎ

自動的な見た目品質判定と画像処理アルゴリズムの変更は今回の対象外とする。
